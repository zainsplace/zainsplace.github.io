An SSRF the docs said couldn't happen

A managed cloud database let me point its snapshot-restore feature at any URL I liked, with nothing more than a normal API key — and make the backend go fetch it. The product's own documentation said this was blocked in the cloud. The source said otherwise, and so did twenty-two out-of-band callbacks.

What it was

The database can restore a snapshot from a URL. On the self-hosted build that is a known, documented capability; the cloud product's documentation stated that outbound URL recovery was disabled there. Reading the code, the fetch client had no server-side-request-forgery guard, and the feature was in fact enabled on the cloud data plane. So an authenticated customer — any standard API key — could ask the service to make an HTTP request to a destination of their choosing: a classic server-side request forgery, on the exact feature the docs claimed was safe.

How I confirmed it

I did not want to rely on reading the source alone, so I proved the request actually left the building. Pointed at an out-of-band listener, the service produced twenty-two DNS callbacks from the provider's own cloud IP ranges — blind SSRF, confirmed on the wire. From there I showed loopback reach: the backend could hit services bound to 127.0.0.1 on the host, with the HTTP status code acting as an oracle for what was and was not listening.

Just as important is where it stopped. External HTTP egress was filtered, the cloud metadata endpoint returned no credentials, and private-range and file:// destinations were blocked. So this was real and reachable, but bounded — Low-to-Medium, not a full internal-network compromise. I reported it at that honest severity rather than inflating it, because a finding you have to oversell is one a triager stops trusting.

How it resolved

The security team closed it as already reported — a duplicate. No bounty, but the outcome confirms the finding: an independent researcher had found the same SSRF, and the vendor agreed it was real. The analysis, the out-of-band proof and the honest bounds all held; the issue was simply already on their desk.

The target stays unnamed here: the report was handled privately through the vendor's program and was never publicly disclosed.

What it shows

Reading source to spot a missing control, then confirming it out-of-band instead of assuming it — and mapping the real blast radius honestly, including everything the control still stopped. A finding is worth more when its limits are stated as clearly as its reach.
