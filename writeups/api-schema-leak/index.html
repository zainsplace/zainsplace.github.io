A public API schema that gave away the back office

A financial-data platform served its full API specification to anyone who asked, no login needed. The spec included the internal order workflow and the names of the firms it settles with. I reported it.

What it was

The schema endpoint returned the platform's OpenAPI 3.0.3 document to an unauthenticated GET. Plenty of APIs publish their schema on purpose, so that alone isn't a bug. The problem was what was in it. The spec was generated from the live back-end models, so as well as the public routes it described the internal order-workflow state machine and named the settlement counterparties.

None of that should be readable without an account. For a financial firm the counterparty names are commercially sensitive, and the workflow is a map an attacker would otherwise have to piece together one endpoint at a time. The fix is small: build the schema from public routes only, or put the endpoint behind the same login as the API it describes. That's probably why it shipped in the first place.
